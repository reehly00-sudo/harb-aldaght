# 🥁 حرب الضغط

لعبة ويب اجتماعية تنافسية سريعة — **تصميم Keep**.
غرف بكود، جولات قصيرة (5–15 ثانية)، ونظام تقدّم XP + Levels + Leaderboard بلا أي عملات.

## التشغيل

المتطلب الوحيد: **Node.js 22.5 أو أحدث**. لا توجد مكتبات خارجية ولا `npm install`.

```bash
cp .env.example .env      # اختياري
npm start                 # http://localhost:3000
npm test                  # اختبار شامل لمباراة كاملة
```

عند أول تشغيل بدون `FOUNDER_KEY` يطبع السيرفر مفتاح المؤسس في الطرفية. الدخول باسم `Keep` يتطلب هذا المفتاح.

## متغيرات البيئة

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `PORT` | `3000` | منفذ السيرفر |
| `DB_PATH` | `./data/game.db` | ملف قاعدة البيانات SQLite |
| `FOUNDER_KEY` | يُولَّد تلقائيًا | مفتاح الدخول لحساب المؤسس Keep |
| `MIN_PLAYERS` | `2` | أقل عدد لبدء المباراة |
| `MAX_PLAYERS` | `10` | أقصى عدد في الغرفة (غيّره لزيادة السعة) |
| `TZ_OFFSET_MIN` | `180` | فرق التوقيت عن UTC لحساب صدارة «اليوم» |

## قاعدة البيانات

تُنشأ تلقائيًا من `src/schema.sql` عند التشغيل، ولا تحتاج أي خطوة يدوية.
الجداول: `users`, `player_progress`, `rooms`, `room_players`, `games`, `rounds`, `scores`, `leaderboard_entries`.
صدارة اليوم والأسبوع تُحسب مباشرة من `leaderboard_entries` فتتحدث تلقائيًا دون مهام مجدولة.

## النشر

- أي خادم أو منصة تشغّل Node 22 مع قرص دائم لملف القاعدة (VPS، Railway، Render، Fly.io…).
- Docker: `docker build -t harb . && docker run -p 3000:3000 -v harb-data:/data -e FOUNDER_KEY=سرّك harb`
- خلف Nginx عطّل التخزين المؤقت لمسار `/api/stream` (السيرفر يرسل `X-Accel-Buffering: no`).
- الغرف الحيّة محفوظة في ذاكرة العملية، لذا شغّل نسخة واحدة من السيرفر.

## البنية

```
server.js               HTTP + SSE + المسارات (بلا مكتبات)
src/schema.sql          مخطط القاعدة
src/db.js               كل استعلامات SQLite
src/users.js            التحقق من الأسماء وحماية اسم Keep
src/xp.js               معادلات XP والمستويات (حتى 200)
src/rooms.js            الغرف، صلاحيات المضيف، محرك الجولات
src/challenges/*.js     تحديات السيرفر (ملف لكل تحدٍّ)
public/                 الواجهة (HTML/CSS/JS خام، RTL، للجوال أولًا)
public/js/challenges.js واجهات التحديات في العميل
test/smoke.js           اختبار شامل
```

## إضافة تحدٍّ جديد

1. أنشئ `src/challenges/اسم.js` بالواجهة الموثقة في `src/challenges/index.js` وأضفه للقائمة.
2. أضف واجهته بنفس الـ `id` في `public/js/challenges.js`.

## الحماية من الغش

- كل النتائج تُحسب في السيرفر؛ العميل يرسل أفعالًا فقط.
- الضغط السريع: سقف 15 ضغطة/ثانية، وتجاوزه بوضوح يلغي نتيجة الجولة.
- رد الفعل: لحظة الإشارة لا يعرفها إلا السيرفر، وأي زمن أقل من 70ms يُرفض.
- لا تضغط / الزر المفخخ: الإشارات ومكان القنبلة في السيرفر فقط.
- حد أدنى زمني بين الأفعال، و30 طلبًا/ثانية لكل لاعب، وحدّ لمحاولات الدخول.

## XP والمستويات

المطلوب للمستوى التالي = `100 + 25 × (المستوى − 1)`. الوصول إلى 200 يحتاج نحو 512 ألف XP،
والمباراة تمنح تقريبًا 30–150 XP حسب النقاط والمركز وعدد اللاعبين والجولات.
